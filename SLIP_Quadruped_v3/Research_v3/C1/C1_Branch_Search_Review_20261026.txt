2. Why even PK has not finished

A. There is no end-to-end range-completion controller.
RunC1Continuation_v3 extends one selected component in one selected direction. Its stopping conditions include accepted-point cap, attempt cap, minimum step, child/time allocation and exception. It does not stop on a verified P1-range completion condition and does not automatically queue both ends of every unresolved component. RunC1Campaign_v3 similarly executes a selected stage, rather than owning a global PK work queue.

The latest PK checkpoint confirms status attempt_cap: it began with 35 points, made five attempts (three accepted and two failed_full_closure), and ended with 38. All five attempt rows were timely. The archived Fresh5 caller explicitly allows only MaxAttempts=5 and MaxAccepted=5, despite a 4200-second outer/3600-second inner allocation. Reaching that cap is not reaching a physical branch endpoint.

The latest wrappers do resume the same output and preserve earlier points; it would be incorrect to say every run starts from scratch. The gap is the absence of a persistent until-range/endpoint controller above those bounded experiments.

B. Recent PK work mostly revisits an existing energy window.
The older stored long-PK component already spans approximately E=9.92546–31.12747. The newest 38-point file ends at E=31.12423827, and the independently qualified positive-clearance roots approach E=31.12746015. Thus those experiments refined/qualified a window already represented in older stored data. They did not extend the overall stored PK energy maximum toward the P1 reference target near208.891. This is a comparison of stored ranges, not proof that every overlapping record is the same physical cycle.

C. There is a real near-grazing difficulty, but no proved endpoint.
The latest owned PK37/38 have local pre-contact swing clearances about8.04e-5 and3.50e-5. Independent square-root solves reached positive clearance targets1e-5,1e-6,3e-7,1e-7. Failed continuation attempts included exhausted admissible-domain Newton fractions and unavailable finite real square Jacobians. These are concrete local obstructions. They do not prove a terminal branch endpoint or that no alternative native route exists.

D. Familiar v2 PK is not automatically the same admissible hybrid branch.
V2 reference shooting integrates prescribed event segments to supplied times. Native v3 follows directed enabled roots and checks swing nonpenetration/compressive stance. Selected reference states either fail initial native admissibility or encounter native contact earlier than the scheduled reference. The state/leg/time roles were checked without finding a conversion fix that resolves those selected cases. Full P1 range/topology inheritance remains unverified. The physical law must not be relaxed to force the expected picture.

E. Scientific qualification and bookkeeping were allowed to dominate progress reporting.
Some budget went to parent/daughter acquisitions, derivative diagnostics, source/serialization repairs and broad retention/publication audits rather than range extension. Whole-file transactional copies and repeated deep readbacks are also real implementation costs. No timing profile establishes their exact share, so a numerical percentage would be invented. Several earlier final censuses timed out. Today's smaller-purpose storage census now exposes substantial existing partial components without claiming new scientific qualification.

The workflow should have delivered a component atlas and current partial branch package earlier, while keeping complete-range and bifurcation work explicitly separate.
