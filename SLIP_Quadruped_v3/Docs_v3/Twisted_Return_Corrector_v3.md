# Front-swap twisted-return experiment

`TwistedReturnFamilyResidual_v3` is an experimental corrector adapter for the registered n0 PIP front-antisymmetric direction. It does not change the hybrid engine, event ownership, physical model, shared acceptance thresholds or campaign state.

Let `P1` be the actual one-BL marked apex return and let `Sf` exchange the FL/FR angle and rate state pairs. The model uses identical parameters within each front pair. This swap preserves the flight apex and the marked BL identity, so wherever the actual return exists its physical symmetry relation is `P1(Sf*x)=Sf*P1(x)`. The corresponding global claim is not made for a hind-leg swap because that changes the marked identity.

The unrestricted flight-apex chart has twelve coordinates `u`; energy `E` is a thirteenth internal unknown. The residual contains eleven components of `P1(x(u))-Sf*x(u)`, one equation `H(x(u))-E`, and one signed-amplitude equation `normal'*( [u;E]-reference )-target`. The omitted closure coordinate is the regular energy pivot, which this front swap must preserve. No energy value is appended to the ten physical model parameters passed to a flow, guard or reset.

This formulation reduces the unexcited flip degeneracy of the bare two-return equation, but it does not establish a simple kernel. At the registered parent, the front flip and a pronk +1 mode can both remain null on the energy leaf. The pilot registration records the actual measured matrix, swap, SVD, nullity threshold and amplitude. Common first-derivative evidence under the recorded event-order hypotheses does not certify unrestricted C2 regularity or a bifurcation theorem.

The adapter deliberately exposes `Map=P2`, the actual two-BL marked map, to the shared service. Its Newton evaluation uses the separate actual `P1` map and retains raw one-return state, event history, signatures and ordinary closure in `one_return_info`. The compatibility metadata supplied to the explicitly opted-in one-return `EventOrderChartJacobian_v3` still describes that actual `P1` evaluation.

When the twisted residual reaches the registered `1e-7` trigger, the adapter additionally evaluates the actual `P2` map and retains it in `two_return_info`. Until this is evaluated successfully, full physical closure is unknown (`Inf`), and no physical closure vector is invented. A valid nonperiodic one-return objective remains usable. Failure of the separate physical two-return evaluation is recorded as `two_return_failure`.

Orbit creation requires actual full BL2 closure at `1e-8`, full twisted closure at `1e-8`, and front angle/rate spread greater than `1e-7`. Its trajectory comes entirely from the actual two-return map. `PeriodicSolutionSolver_v3` then constructs a new simulator and actual BL2 map at tighter tolerances, replays twice, and applies its unchanged full-state, energy, stance, deterministic-replay and primitive-cycle gates. A renamed or leg-swapped one-return trajectory can never provide the accepted orbit. Nonzero spread motivates a two-return candidate; the actual primitive-period gate supplies the numerical evidence against a one-cycle cover.

Usage follows the existing delegated residual interface:

```matlab
adapter = TwistedReturnFamilyResidual_v3(oneFamily,twoFamily,constraint);
options = struct('Residual',adapter,'Coordinates',[u;E], ...
    'AugmentedParameter',[physicalParameter;E], ...
    'MaxWallSeconds',240,'SolverOptions',solverOptions);
[orbit,report] = PeriodicSolutionSolver_v3(seedWithOccurrence2,options);
```

Both families must use matching unrestricted flight-apex charts, fixed physical parameters and reference states; their actual policies must have BL counts one and two respectively. The amplitude normal is front antisymmetric and has zero energy component. This narrow adapter does not implement stance charts, hind marking transport or a paired-spread invariant restriction.

The focused runner `Research_v3/next_round/solver/PilotTwistedFrontReturn_v3.m` reads the existing n0 parent admission and measured front direction with MATLAB, saves its registration before evaluation, checks physical front-swap equivariance on the nonzero seed, and invokes one shared-service pilot with a 240-second correction budget. Its `twisted_return` artifacts preserve initial/raw one-return, actual two-return, independent replay, failed candidate and classification evidence. Acceptance or failure is an observed numerical result, without ancestry or new-gait claims.
