# State-based diagnostics and local BL apex charts

The new services live in `Orbit_v3` and require only the v3 schema, dynamics, simulation, and orbit paths. They do not call the legacy classifier, modify event eligibility, or select itineraries from desired gait names.

`GaitIdentification_v3(source, options)` accepts `Trajectory_v3`, `HybridOrbit_v3`, or an orbit struct containing a complete trajectory, period, parameter vector and event log. It returns descriptive labels, legacy display colors/abbreviations, all TD/LO occurrences and circular phases, duty factors, contact functions, sampled angle/rate trajectories, contact and motion synchronization residuals, front/hind pairing, signed right-minus-left lead, event clusters, sampled suspension geometry, numerical primitive diagnostics and physical flight count. `HB_front`/`F2` always means front spread; `HB_hind`/`H2` always means hind spread. The explicit display mapping is `GaitSemanticTable_v3`. Legacy suffix 2 was a timing heuristic; v3 reports the physical count separately and uses a 2 display suffix only for a numerically identified two-flight record. Names and colors carry no dynamical or isotropy proof.

`PrimitiveCycleCheck_v3` first checks translated endpoint closure, mode closure, and presence of logged contact-mode changes. It then tests integer covers 2 through a declared bound (default 8), using complete physical state modulo horizontal translation, both event sides, contact history, all event phases and per-event multiplicity. A leg-relabelled shorter return is not a cover under this test. A detected double cover is counted over its numerically identified shorter period. An unclosed or incompletely logged record keeps status `unknown` and physical primitive flight count `NaN`. The status `primitive_within_checked_bound` is finite sampled numerical evidence, not a mathematical proof of minimal period. An exact recorded shorter full-state return that conflicts with sampled interior comparisons is conservatively `unknown` and requires independent replay, rather than counting its recorded double cover as a two-flight gait. Higher covers, interpolation errors, unresolved fast state variation and essential unrecorded auxiliary state remain outside its certificate.

Flight intervals are computed from recorded modes on open positive-duration spans. Adjacent flight spans merge, including the span wrapping across the selected phase boundary. Isolated zero-duration contact events do not introduce a counted interval. Every result retains raw positive-duration counts and counts at 0.1, 1 and 10 times the configured duration threshold; disagreement marks a tolerance boundary. Contact synchronization uses exact durations of the piecewise-constant recorded contacts; motion synchronization uses an explicitly recorded sample count and tolerance. Contact equality conflicting with angle/rate equality is classified ambiguous. Equal timings alone never imply full-state isotropy. Gathered/extended descriptions use sampled front/hind foot spread relative to the hips throughout each suspension rather than the sign of initial body pitch.

`CircularPhase_v3.wrap` is an interface operation. `difference` is a shortest local circle displacement. `liftNear` provides an integer chart transition and a continuous local lift near a supplied reference; an exactly ambiguous half-turn throws an explicit error. Continuation using event-phase quantities must carry these lifts and transition integers rather than subtracting raw wrapped coordinates.

## Optional BL-marked return policy

The existing `EventCycleReturnPolicy_v3` remains the quadruped default for compatibility. It selects a labelled cycle with at least one TD/LO per leg and mode closure; it does **not** certify a primitive period. Use the independent primitive diagnostics for that question.

`BLMarkedApexReturnPolicy_v3` can instead be passed explicitly to `PoincareMap_v3`. The initial chart requires that the next BL touchdown occur strictly between the initial downward apex and the next downward apex. The selected apex is consequently the last qualifying apex strictly before that touchdown, with no intervening BL touchdown. A first-return lookahead uses the same autonomous system, simulator and geometric section for this predicate. The rule applies to nearby nonperiodic initial states without evaluating a periodic residual. Its default return has exactly one intervening BL touchdown; `BLTouchdownsPerReturn=N` explicitly selects an iterated labelled return. Each candidate must satisfy the same next-TD marking and, by default, right-continuous mode closure. Neither a state-distance test nor a target gait label changes this map.

The map propagates the section chart, mode, downward orientation, selected initial/return BL occurrences, apex return multiplicity, post-reset ownership, elapsed time, translation gauge and positive marking separation margins into the return info and `HybridOrbit_v3`. Lookahead integration is part of its computational cost and uses explicit limits. An occurrence passed before a qualifying apex, BL TD/apex coincidence, absent next apex, lost transversality or changed event identity is a local chart boundary or failure. The strict-before chart deliberately does not silently reinterpret BL touchdown coincident with a section crossing; the general geometric return still processes such contact clusters using its existing post-reset convention. Grounded apexes are eligible whenever their physical mode and downward transversality are admissible.

`RephaseHybridOrbit_v3` supplies a data overlap predictor: it rotates all physical states/modes/events/batches, preserves event sides, accumulates relative horizontal drift, and sets x=0 at the new initial point. Its output and report explicitly require correction and independent forward replay. It does not certify a new apex, a periodic solution, or a symmetry. For a legitimate system leg symmetry g, chart transport must apply g to the **complete** orbit then rephase onto the selected chart; BL marking alone is not equivariant under an arbitrary leg permutation. Corrected physical overlap examples for distinct B2 apex views remain an execution gate, and no new system symmetry is asserted here.

## Validation and limits

The executed MATLAB contract checks covered both half-bound orientations, phase shifts and invertible data overlaps, within-pair relabeling, simultaneous contacts, unequal duty factors, tiny flight tolerance sensitivity, missing event history, double covers, circular phase wrap, nonperiodic local BL return, explicitly repeated BL occurrence, apex/TD coincidence rejection, and existing default policy compatibility. Test sources and temporary check scripts were removed during the 2026-10-07 cleanup. The preserved physical record is `Research_v3/Audits_v3/physical_validation.mat`; it contains exact parameters, seed, return information, primitive/classification diagnostics and a rephased predictor. The aggregate verification record is `Research_v3/Audits_v3/final_summary.json`. Synthetic checks isolate contracts and are not physical branch-switch evidence. The physical vertical check alone cannot establish the B2 two-apex overlap, grounded apex, grazing transition, front/hind daughter attachment or P1/P2 network.
