# Near-grazing delayed fixture and earliest-event output

The exact campaign replay of `P2_All_Common_Quadrupedal_Gaits/SourceFixtures_v3/PIP_Delayed_Analytic_10_20_2.mat`, column 1, produced a nonchronological trajectory. This was reproduced under the original framework settings and saved before the fix; the record is retained in `Research_v3/Audits_v3/delayed_boundary_diagnosis.mat`. The seed is all stance, with y=1.0000000001, zero vertical speed and zero angles/rates, at p=[10,10,20,20,1,1,0,0,2,0.5]. Its legacy scheduled period is 1.9869176531592956. The old autonomous event-cycle map reported period 2.9803764796238026 and endpoint residual 1.2613643463055269e-10, but neither value certifies a valid primitive cycle.

The decisive symptom is a time reversal at trajectory row 501: 0.99344890782598694 followed by 1.7347234759768071e-18, a jump of approximately -0.9934489. This is far larger than floating-point rounding. `GaitIdentification_v3` correctly raised `HybridCycleData_v3:InvalidStateHistory`; sorting the samples would hide the execution error and is not an acceptable correction.

The detector selected the earliest raw ODE event time, approximately zero, while appending all ODE output through a later event near 0.9934489 before applying that earlier reset. MATLAB can return later output when a terminal event is reported near its first step; this behavior is explicitly documented by [MathWorks ODE Event Location](https://www.mathworks.com/help/matlab/math/ode-event-location.html). `EventDetector_v3` now truncates the continuous segment strictly before the selected earliest event and appends its exact event state at that event time. Flow after the selected reset belongs to a different mode and must be recomputed there.

The same initial raw event also violated the existing physical directed transverse-root predicate. The detector previously accepted a triggered channel unconditionally, bypassing the guard direction and Lie-derivative checks applied to simultaneous neighbors. It now evaluates the same root value, orientation and existing derivative tolerance for a triggered guard or section and raises `IneligibleTriggeredGuard` or `IneligibleTriggeredSection` when this contract fails. This uses the existing configured derivative threshold; it does not raise that threshold to exclude arbitrary valid boundary solutions. A tangency or unsupported numerical event is recorded as a map boundary/failure, not converted into an ordinary transverse return.

The post-fix replay of the original source and configuration asserted the named rejection; its record is `Research_v3/Audits_v3/delayed_boundary_fixed.mat`. The executed earliest-event contract check also isolated MATLAB output extending beyond an earlier reported terminal event and required that no such later sample enter the pre-reset trajectory. Its physical regression required rejection of the spurious initial contact. Test sources and temporary check scripts were removed during the 2026-10-07 cleanup. The ordinary physical vertical marked-apex example remains separately recorded in `Research_v3/Audits_v3/physical_validation.mat`, with y=1.1 and full-state closure below 1e-8.

The callback's existing guard-arming implementation changes an arming flag while ODE event callbacks run. Near-initial or nearly tangent events can remain sensitive to adaptive callback evaluation order. The present correction prevents invalid event acceptance and impossible chronology; it does not establish smoothness, full reliability at grazing, or an admissible continuation through that boundary. A valid boundary treatment needs an explicit local model/chart and an event law with independently validated limiting behavior. Endpoint closure alone cannot supply it. The all-stance seed y>1 is also slightly outside strict compressive stance (within numerical admissibility tolerance) and its energy is below the registered campaign lower bound 1.0001. It must not establish a regular delayed-PIP seed or network edge.

An effective-settings issue is distinct: passing tolerances only through `ODEOptions` does not override the simulator's top-level default `RelTol`/`AbsTol`, which the detector reapplies. The original campaign wrapper consequently used absolute tolerance 1e-11 rather than the file's 1e-10. The diagnostic matches that original behavior; final campaign wrappers must pass top-level tolerances and retain their effective values.

## Small-height flight incorrectly joined to a section arming stop

A second independent reproducer starts in flight at y=1+1e-8 and zero rates. The exact falling flight has TD time `sqrt(2*(y-1))=1.41421355807567e-4`. Before the second correction, all four legs touched down at the artificial leave-apex arming stop t=1e-7, with nonzero guard value 9.99999483219938e-9. The absolute guard-value tolerance alone treated this near-grazing guard as simultaneous with that section stop even though its estimated root time was far away. These are the observed pre-fix values; temporary red/green test payloads were removed during cleanup.

Cluster membership now requires the surface value to satisfy `EventValueTolerance` **and**, whenever DgF is nonzero, the independent estimate `abs(g/DgF)` to satisfy `SimultaneousTimeTolerance`. The original directed-root check remains. No tolerance was loosened or changed. An explicitly nondirectional zero-speed guard has no linear root-time estimate and retains its value contract; directed zero-speed roots remain unsupported by the transverse detector. This local time estimate is not a proof of smoothness near grazing.

The corrected regression required all four TD times within 1e-9 of the physical benchmark and guard residuals below 1e-12. The ordinary y=1.1 case retained four simultaneous TD and four LO events. MATLAB R2025b passed all 31 affected tests: four earliest-event regressions, thirteen return-policy contracts, four event-batch tests, five event-cluster tests and five BL-marked-section tests. The retained aggregate verification record is `Research_v3/Audits_v3/final_summary.json`; the final fixture replay is `Research_v3/runs/full/compatibility.json`. That replay uses both detector corrections; earlier compatibility entries are superseded. Ordinary PIP column 1 remains below the registered energy lower bound even when its numerical timing is repaired.
